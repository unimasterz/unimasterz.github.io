got: agents per protocol

The most complete of the Node clients for unattended work: proper retries, hooks, and a timeout object with a genuine total. The setting goes in an unusual place. Tested against got 14.

The setting

import got from "got";
import { HttpProxyAgent } from "http-proxy-agent";
import { HttpsProxyAgent } from "https-proxy-agent";

const line = "http://user:pass@198.51.100.14:8080";

const client = got.extend({ agent: { http: new HttpProxyAgent(line), https: new HttpsProxyAgent(line), }, timeout: { request: 30_000, connect: 5_000, response: 20_000 }, retry: { limit: 3 }, }); ```

The agent object is keyed by the protocol of the target, and both values point at the same hop. Same shape as the Python dict, same reason people fill it in wrongly.

Supplying only https is the usual mistake. It works until a redirect sends you to a plain http url, which then goes direct.

Timeouts, with a real total

timeout: {
  lookup: 2_000,     // резолв имени
  connect: 5_000,    // до соединения
  secureConnect: 5_000,  // рукопожатие
  socket: 10_000,    // тишина в сокете
  response: 20_000,  // до первого байта
  request: 45_000,   // весь вызов целиком
}

request is a genuine ceiling on the whole call including retries, which almost nothing else in this reference offers without extra machinery. If you set one value, set that one.

Retries that are actually configurable

retry: {
  limit: 3,
  methods: ["GET", "HEAD"],
  statusCodes: [408, 413, 429, 500, 502, 503, 504],
  errorCodes: ["ETIMEDOUT", "ECONNRESET", "ECONNREFUSED", "EPIPE"],
  calculateDelay: ({ attemptCount, error }) => {
    if (attemptCount > 3) return 0;
    const posle = Number(error?.response?.headers?.["retry-after"]);
    if (posle) return Math.min(posle * 1000, 900_000);
    return (2 ** attemptCount) * 300 + Math.random() * 300;
  },
}

calculateDelay returning zero stops the retries. Note the two things this does that most defaults do not: it honours the server's own retry-after, and it adds randomness so parallel workers do not retry in unison.

Hooks, and why they matter here

hooks: {
  beforeRequest: [(opt) => { opt.headers["x-run"] = RUN_ID; }],
  beforeRetry: [(err, count) => {
    console.warn(`повтор ${count}: ${err.code ?? err.response?.statusCode}`);
  }],
  beforeError: [(err) => {
    err.message = `${err.message} [${err.options?.url?.host}]`;
    return err;
  }],
}

beforeRetry is the one worth wiring up on day one. Without it, retries are invisible and a job that quietly retries a third of its requests looks identical to one that does not.

Rotating

Because the agent lives in options, a per-request route is a per-request agent:

await client.get(url, {
  agent: { http: agents[i].http, https: agents[i].https },
});

Build the agents once into an array and index into it. Creating agents per request throws away the connection pool and costs you the reuse you were trying to get.

Bypass

No bypass list. Route in your own code by choosing which extended client to call, which is the same explicit approach undici forces and is easier to reason about than a matching string.

const cherez = got.extend({ agent: { http: a, https: b } });
const pryamo = got.extend({});

const vybrat = (u) => u.includes(".internal") ? pryamo : cherez; await vybrat(url).get(url); ```

Confirming it works

console.log("got выходит через", (await client("https://api.ipify.org")).body.trim());

Test both protocols separately. The single-key mistake is common enough that it is worth two lines rather than one.
