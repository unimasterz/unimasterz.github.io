axios: the proxy option that quietly does not apply

axios has a proxy option, which is why people assume it works everywhere. For encrypted targets it does not do what the name suggests. Tested against axios 1.7.

The five answers

QuestionAnswer for axios
Where the setting goeshttpsAgent for real work, proxy for plain http only
Environment overrideyes, and it respects NO_PROXY
Who resolves the nameyour machine
Certificatesverified against the real target
The trapthe proxy option is quietly wrong for https targets

The trap, stated plainly

// выглядит правильно, для https целей работает не так, как ожидается
const r = await axios.get("https://example.com", {
  proxy: { host: "198.51.100.14", port: 8080 },
});

For an encrypted target this does not open a tunnel the way a browser or curl would. Depending on version and target you get a certificate error, a plain-text request where you expected a tunnel, or something that appears to work but is not the shape you think.

The reliable form is an agent:

import axios from "axios";
import { HttpsProxyAgent } from "https-proxy-agent";
import { HttpProxyAgent } from "http-proxy-agent";

const line = "http://user:pass@198.51.100.14:8080";

const client = axios.create({ httpAgent: new HttpProxyAgent(line), httpsAgent: new HttpsProxyAgent(line), proxy: false, // выключаем встроенный механизм timeout: 20_000, }); ```

Three parts and all three matter. The https agent handles encrypted targets. The http agent handles plain ones. And proxy: false stops axios from also applying its own handling on top, which is where the confusing double behaviour comes from.

`proxy: false` is not optional here

Without it, axios may apply both its built-in mechanism and your agent. The result varies by version and it is never what you wanted.

The environment

Unlike global fetch, axios does read the environment, and it honours the bypass list.

VariableRead
HTTP_PROXY, http_proxyyes
HTTPS_PROXY, https_proxyyes
NO_PROXY, no_proxyyes

This means a script that works on your machine may behave differently on a server where those are set, and vice versa. proxy: false plus explicit agents removes the environment from the picture entirely, which for a scheduled job is what you want.

Bypass

If you keep the built-in mechanism, NO_PROXY works with the usual comma-separated syntax. If you use agents, the bypass is your own code:

const pryamoAgent = undefined;
const client = axios.create({ proxy: false });

client.interceptors.request.use((cfg) => { const host = new URL(cfg.url, cfg.baseURL).hostname; const vnutri = host.endsWith(".internal"); cfg.httpsAgent = vnutri ? pryamoAgent : httpsCherez; return cfg; }); ```

Timeouts

axios.create({ timeout: 20_000 });

One number, and it covers the response, not the connection. A connection that never establishes can sit longer than this value in some situations.

For a genuine ceiling, use a signal:

await client.get(url, { signal: AbortSignal.timeout(45_000) });

Retries

Nothing built in. The common package is axios-retry:

import axiosRetry from "axios-retry";

axiosRetry(client, { retries: 3, retryDelay: axiosRetry.exponentialDelay, retryCondition: (e) => axiosRetry.isNetworkOrIdempotentRequestError(e) || e.response?.status === 429, }); ```

exponentialDelay includes a small random component, which is better than the plain backoff several other clients ship with.

Confirming it works

const { data } = await client.get("https://api.ipify.org");
console.log("axios выходит через", String(data).trim());

Check both schemes if your job touches both. It is entirely possible to have the https agent configured and the http one missing, and then a single plain-http redirect target goes direct without a word.
