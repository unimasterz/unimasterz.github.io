Wirebound / Node.js

Global fetch and undici: ProxyAgent or nothing

Every guide written before Node 18 is wrong about this. Global fetch does not read HTTP_PROXY, does not read NO_PROXY, and has no proxy option. Tested against Node 20 and 22 with undici 6.

sponsor

The five answers

QuestionAnswer for global fetch
Where the setting goesan undici ProxyAgent, per call or globally
Environment overrideno, nothing is read
Who resolves the nameyour machine
Certificatesverified against the real target
The trapit fails silently, going direct with no warning

The problem

// это НЕ работает, ни в одном виде
process.env.HTTP_PROXY = "http://198.51.100.14:8080";
const r = await fetch("https://example.com");   // идёт напрямую

No error. No warning. The request goes direct and everything appears fine, which is precisely why this costs people days. Node's fetch is undici underneath and undici was designed to take a dispatcher rather than read the environment.

Per call

import { ProxyAgent } from "undici";

const agent = new ProxyAgent("http://user:pass@198.51.100.14:8080");

const r = await fetch("https://example.com", { dispatcher: agent }); ```

dispatcher is not part of the fetch standard, which is why editors and type definitions sometimes complain about it. It works.

Create the agent once and reuse it. A new agent per call means a new connection pool per call, and you pay full setup on every request.

Globally, for the whole process

import { setGlobalDispatcher, ProxyAgent } from "undici";

setGlobalDispatcher(new ProxyAgent("http://user:pass@198.51.100.14:8080"));

// теперь любой fetch в процессе идёт через него const r = await fetch("https://example.com"); ```

This is what most jobs want. One line at startup and every library in the process that uses global fetch is covered, including ones you did not write.

It covers global fetch and nothing else

A library that imports axios, got, or node:https directly is unaffected by setGlobalDispatcher. If you have a mixed dependency tree, the global dispatcher covers part of it and you have to handle the rest separately.

Reading the environment yourself

Since nothing does it for you, do it explicitly and visibly:

import { setGlobalDispatcher, ProxyAgent, Agent } from "undici";

const line = process.env.HTTPS_PROXY || process.env.https_proxy || process.env.HTTP_PROXY || process.env.http_proxy;

setGlobalDispatcher(line ? new ProxyAgent(line) : new Agent()); console.log(line ? через ${new URL(line).host} : "напрямую"); ```

That log line at startup is worth having permanently. It converts an invisible default into a visible statement.

Bypass

ProxyAgent has no bypass list. NO_PROXY does nothing. If some hosts must go direct, you route in your own code:

const pryamo = new Agent();
const cherez = new ProxyAgent(line);

const vybrat = (u) => new URL(u).hostname.endsWith(".internal") ? pryamo : cherez;

await fetch(url, { dispatcher: vybrat(url) }); ```

Verbose, and it is explicit about a decision that other clients hide behind a string with implementation-specific matching rules.

Timeouts

const agent = new ProxyAgent({
  uri: "http://198.51.100.14:8080",
  connectTimeout: 5_000,
  headersTimeout: 20_000,
  bodyTimeout: 30_000,
});

Three clocks and no total. For a hard ceiling, use an abort signal, which is the standard mechanism and does bound the whole call:

const r = await fetch(url, {
  dispatcher: agent,
  signal: AbortSignal.timeout(45_000),
});

AbortSignal.timeout is the cleanest total-time ceiling available in any client in this reference. Use it.

Connections

new ProxyAgent({
  uri: line,
  connections: 20,        // на хост назначения
  pipelining: 1,
  keepAliveTimeout: 30_000,
});

The default connection count is low. A job with fifty concurrent requests against one host and default settings queues internally, and the symptom looks like a slow target.

The other family

ProxyAgent speaks HTTP only. For the other scheme family you need a separate package that supplies a socks dispatcher, or a local relay. There is no built-in support.

Confirming it works

const r = await fetch("https://api.ipify.org", { dispatcher: agent });
console.log("fetch выходит через", (await r.text()).trim());

Run it at startup and stop the process if the address matches the machine. Because the failure mode here is silence, this check matters more in Node than anywhere else in this reference.
