httpx: explicit mounts, async transport, trust_env

httpx looks like requests until the moment it does not. The dict is gone, the routing is explicit, and the async client has its own set of surprises. Tested against httpx 0.27 on Python 3.11.

The simple form

import httpx

with httpx.Client(proxy="http://user:pass@198.51.100.14:8080", timeout=httpx.Timeout(20.0, connect=5.0)) as c: r = c.get("https://example.com") ```

One value, applied to everything the client does. This covers most jobs.

There is no per-request proxy argument

In requests you can pass proxies= to a single call. httpx deliberately does not allow this, because routing is a property of the transport. If different calls need different routes, you need different clients, or mounts.

Mounts, when one value is not enough

The mounts mapping routes by url pattern, and it is more capable than the old dict because the keys are patterns rather than just schemes.

c = httpx.Client(mounts={
    "http://":  httpx.HTTPTransport(proxy="http://198.51.100.14:8080"),
    "https://": httpx.HTTPTransport(proxy="http://198.51.100.14:8080"),
    "all://internal.example": None,     # this host goes direct
})

A value of None means no proxy for anything matching that pattern, which is how you carve out exceptions. Patterns are matched most specific first, so the host entry above beats the two scheme entries.

This is the cleanest bypass mechanism of any client in this reference. Most others rely on a no_proxy string with matching rules that vary between implementations.

trust_env

Same idea as requests, same default, and worth knowing about for the same reason.

c = httpx.Client(proxy=LINE, trust_env=False)

With trust_env left on, the standard environment variables are read and applied. Unlike requests, httpx treats an explicit proxy= argument as the stronger signal, so your code wins. The environment still matters when you pass nothing.

nothing set, trust_env=Trueenvironment used
nothing set, trust_env=Falsedirect

Async is a separate client

AsyncClient takes the same arguments, but the transport class is different and mixing them silently gives you the wrong one.

import httpx, asyncio

async def main(): async with httpx.AsyncClient( proxy=LINE, limits=httpx.Limits(max_connections=20, max_keepalive_connections=10), timeout=httpx.Timeout(20.0, connect=5.0), ) as c: rs = await asyncio.gather(*(c.get(u) for u in urls))

asyncio.run(main()) ```

For mounts in async, use httpx.AsyncHTTPTransport. Passing the sync HTTPTransport to an async client raises, which is at least a loud failure rather than a quiet one.

limits is the setting people miss. The default number of connections is modest, and firing a thousand coroutines at a client with default limits gives you a queue, not concurrency.

The other family

Not built in. Install the extra:

pip install "httpx[socks]"

Then pass socks5:// in the same place. As of 0.27 httpx does not accept the socks5h spelling; resolution behaviour is decided by the underlying library rather than by a letter in the scheme. If where the lookup happens matters to your job, run probe two and find out for your version instead of assuming either way.

Timeouts are four numbers, not one

httpx splits the clock further than most clients, and this is a genuine advantage once you know it exists.

httpx.Timeout(
    timeout=20.0,   # default for anything not named below
    connect=5.0,    # establishing the connection
    read=20.0,      # waiting for a chunk
    write=10.0,     # sending the request body
    pool=5.0,       # waiting for a free connection from the pool
)

The pool clock is the one worth setting deliberately. Without it, a job with more workers than connections waits silently inside the client, and the symptom looks like a slow target.

Confirming it works

with httpx.Client(proxy=LINE, timeout=15) as c:
    print("httpx is going out through:", c.get("https://api.ipify.org").text.strip())

If you are using mounts, check each pattern separately. A mounts mapping that looks right can still leave one scheme unrouted, and the direct one is always the one you forget.
