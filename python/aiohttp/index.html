aiohttp: why per-request beats per-session here

The one client here where per-request is the normal way and session level is the exception. That inversion catches everyone arriving from requests. Tested against aiohttp 3.9 on Python 3.11.

The trapsession = ClientSession(proxy=...) is not a thing

Per request, not per session

import aiohttp, asyncio

PROXY = "http://user:pass@198.51.100.14:8080"

async def main(): timeout = aiohttp.ClientTimeout(total=45, connect=5, sock_read=20) async with aiohttp.ClientSession(timeout=timeout) as s: async with s.get("https://example.com", proxy=PROXY) as r: body = await r.text() ```

ClientSession has no proxy argument. People write it anyway, get a TypeError, and go looking for the right keyword. There isn't one at that level.

Wrap the call instead of repeating yourself

Passing proxy= at forty call sites is how one of them ends up missing it. Write one small helper that every call goes through, and the setting exists in exactly one place.

async def fetch(s, url, **kw):
    return await s.get(url, proxy=PROXY, **kw)

The environment is ignored by default

Unusual among the clients here, and worth knowing in both directions.

s = aiohttp.ClientSession(trust_env=True)

With trust_env=True the standard variables are read and applied, and .netrc is consulted for credentials. Without it, aiohttp does exactly what your code says and nothing else.

For a scheduled job this default is a feature: nothing a shell profile does can change how your run behaves.

Credentials

Two ways, and the second avoids the encoding problem entirely.

# in the url
proxy = "http://user:pass@198.51.100.14:8080"

# as a separate object, no percent-encoding needed auth = aiohttp.BasicAuth("user", "pa:ss@word") await s.get(url, proxy="http://198.51.100.14:8080", proxy_auth=auth) ```

The second form is the better habit. A password with punctuation in it never touches url parsing.

Concurrency limits live on the connector

This is the setting that decides whether your run is fast or merely busy.

conn = aiohttp.TCPConnector(
    limit=30,            # total simultaneous connections
    limit_per_host=8,    # per target host
    ttl_dns_cache=300,   # seconds to remember a lookup
)
async with aiohttp.ClientSession(connector=conn, timeout=timeout) as s:
    ...

The default limit is 100 and limit_per_host is 0, meaning unlimited per host. Firing a few hundred coroutines at one host with the defaults is how people discover the reset failure described in the traps section.

Set limit_per_host deliberately. Start low, watch the failure rate, walk it up.

Timeouts

aiohttp.ClientTimeout(
    total=45,        # the whole call, and this one actually exists here
    connect=5,       # getting a connection, including from the pool
    sock_connect=5,  # the socket connect itself
    sock_read=20,    # between chunks
)

aiohttp is one of the few clients in this reference with a real total. Use it. It is the ceiling that other libraries make you build yourself.

The other family

pip install aiohttp_socks
from aiohttp_socks import ProxyConnector

conn = ProxyConnector.from_url("socks5://user:pass@198.51.100.14:1080", limit=30) async with aiohttp.ClientSession(connector=conn) as s: ... ```

Note this moves the setting from the request to the connector, so with this package the session-level form does exist and the proxy= argument is no longer used. Two different mechanisms depending on which scheme family you are on, which is worth a comment in your code so the next reader is not confused.

The socks5h spelling is accepted by aiohttp_socks and does move resolution to the far end. Confirm with probe two.

Cleaning up

An unclosed session prints a warning at interpreter exit and leaks connections while running. Always use the context manager, and if you keep a session on an object, close it explicitly:

await session.close()
await asyncio.sleep(0)   # let the transports finish closing

The short sleep is the documented way to avoid the noisy shutdown warning on some platforms.

Confirming it works

async with aiohttp.ClientSession() as s:
    async with s.get("https://api.ipify.org", proxy=PROXY) as r:
        print("aiohttp is going out through:", (await r.text()).strip())

Because the setting is per request here, check the helper you actually use rather than a fresh call written for the test. The whole point of the check is to catch the call that forgot the argument.
