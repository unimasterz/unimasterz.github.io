Selenium and Playwright from Python: two different setting paths

Both drive a real browser from Python and they disagree about where the setting belongs. The practical difference is whether you can have two identities in one process. Tested against Selenium 4.20 and Playwright 1.44.

Selenium

from selenium import webdriver

opts = webdriver.ChromeOptions() opts.add_argument("--proxy-server=http://198.51.100.14:8080") opts.add_argument("--proxy-bypass-list=<-loopback>") drv = webdriver.Chrome(options=opts) ```

That is the whole mechanism, and it comes with one significant limitation.

Chrome does not accept credentials in that flag

--proxy-server=http://user:pass@host:port does not authenticate. Chrome ignores the credentials and you get an authentication dialog that no automation can dismiss.

The workarounds, in order of how much I would recommend them:

Use a bound address. Your machine is on the allowlist, nothing to authenticate, flag works as written. Simplest by a distance and it is why bound access exists. Providers that support it, IPv4 packages with a bound-address mode among them, let you register the server address in the panel and the whole credential problem disappears.

Run a local relay. A small process listening on localhost that speaks to the hop with credentials. The browser points at localhost with no credentials at all. Robust, and it works identically for every browser and every tool on the machine.

Ship an extension. Chrome extensions can supply credentials programmatically. This works and it means building and loading an extension per identity, which is a lot of machinery for what a relay does with a config line.

The bypass list is worth setting. <-loopback> means loopback traffic goes direct, which stops the driver's own communication with the browser going through the hop.

Firefox in Selenium

Firefox does accept a profile-level configuration and is less awkward here:

from selenium import webdriver
opts = webdriver.FirefoxOptions()
opts.set_preference("network.proxy.type", 1)
opts.set_preference("network.proxy.http", "198.51.100.14")
opts.set_preference("network.proxy.http_port", 8080)
opts.set_preference("network.proxy.ssl", "198.51.100.14")
opts.set_preference("network.proxy.ssl_port", 8080)
opts.set_preference("network.proxy.socks_remote_dns", True)
drv = webdriver.Firefox(options=opts)

socks_remote_dns is the Firefox equivalent of the trailing h: it moves name resolution to the far end. If where lookups happen matters, this preference is the switch.

Playwright

Playwright handles credentials properly, which removes the whole relay question for most jobs.

from playwright.sync_api import sync_playwright

with sync_playwright() as p: br = p.chromium.launch(proxy={ "server": "http://198.51.100.14:8080", "username": "user", "password": "pass", }) page = br.new_page() page.goto("https://example.com", timeout=30000) ```

Note the shape: server without credentials, credentials as separate keys. No url encoding, no dialog.

Per context, which is the real advantage

br = p.chromium.launch()          # без настройки
ctx_a = br.new_context(proxy={"server": "http://a:8080"})
ctx_b = br.new_context(proxy={"server": "http://b:8080"})

Two contexts in one browser process, two different routes, isolated storage. This is the thing Selenium cannot do without launching two browsers.

Rules for how the two levels interact:

Set at launchSet on contextResult
yesnolaunch value used
yesyescontext value used, entirely
noyescontext value used
nonodirect

The context value replaces the launch value; it does not merge with it. A context that sets only server and omits credentials does not inherit the credentials from launch.

Launch with a placeholder if you plan to use per-context values

On some versions, a browser launched with no proxy at all will not accept a per-context proxy for every browser engine. Launching with {"server": "http://per-context"} as a placeholder avoids that surprise, and every context overrides it anyway.

Bypass

br = p.chromium.launch(proxy={
    "server": "http://198.51.100.14:8080",
    "bypass": "localhost,127.0.0.1,*.internal",
})

Comma separated, no spaces. This is the value Chrome would take in --proxy-bypass-list, so the same matching rules apply.

Confirming it works

page.goto("https://api.ipify.org")
print(page.inner_text("body").strip())

For Playwright with several contexts, check each context separately. A context that quietly fell back to direct looks identical to one that did not until you ask it.
