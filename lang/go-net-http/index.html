Go: Transport, ProxyFromEnvironment, and the DNS side

The only runtime in this reference that deliberately refuses one of the environment variables, and the one whose bypass list behaves least like the others. Tested against Go 1.22.

sponsor

The five answers

QuestionAnswer for Go
Where the setting goesTransport.Proxy, a function
Environment overrideyes, on by default
Who resolves the nameyour machine
Certificatesverified against the real target
The trapa bare domain in no_proxy does not cover subdomains

The default already reads the environment

package main

import ("fmt"; "io"; "net/http")

func main() { // http.DefaultTransport уже использует ProxyFromEnvironment r, err := http.Get("https://api.ipify.org") if err != nil { panic(err) } defer r.Body.Close() b, _ := io.ReadAll(r.Body) fmt.Println(string(b)) } ```

With https_proxy set, that goes through the hop with no code at all. Convenient, and it means a Go binary can change behaviour between machines without anything in the source changing.

Setting it explicitly

u, _ := url.Parse("http://user:pass@198.51.100.14:8080")

tr := &http.Transport{ Proxy: http.ProxyURL(u), MaxIdleConns: 100, MaxIdleConnsPerHost: 20, IdleConnTimeout: 90 * time.Second, TLSHandshakeTimeout: 10 * time.Second, ResponseHeaderTimeout: 20 * time.Second, } c := &http.Client{Transport: tr, Timeout: 45 * time.Second} ```

MaxIdleConnsPerHost defaults to 2, which is the setting that surprises people most. A concurrent job against one host with the default opens and closes connections constantly, and the symptom is a slow target that is not slow.

Client.Timeout is a genuine total: it covers the connection, any redirects, and reading the body. Go is one of the few here where the obvious setting is the ceiling you actually want.

Routing per request

Proxy is a function, so the decision can depend on the request:

tr := &http.Transport{
    Proxy: func(req *http.Request) (*url.URL, error) {
        if strings.HasSuffix(req.URL.Hostname(), ".internal") {
            return nil, nil          // напрямую
        }
        return url.Parse(vybratLiniyu(req))
    },
}

Returning nil, nil means direct. This is the cleanest per-request routing of any client in this reference, because it is a plain function instead of a matching string.

The CGI refusal

// из исходников net/http
// An environment without a REQUEST_METHOD is not a CGI environment,
// so HTTP_PROXY is honoured. With one, it is ignored.

If REQUEST_METHOD is set in the environment, Go ignores uppercase HTTP_PROXY entirely. This protects against a remote visitor setting a Proxy header that arrives as HTTP_PROXY in a CGI process.

Practical consequence: a Go program running under something that sets REQUEST_METHOD will ignore HTTP_PROXY while honouring https_proxy. Diagnosing that from the symptom alone is unpleasant, so it is worth knowing the rule exists.

The bypass list, which is the real trap

`no_proxy=example.com` does not match `api.example.com` in Go

In curl and in Python, a bare domain covers its subdomains. In Go it matches that host only. This single difference is why a bypass that works on your laptop fails on a server, or the reverse.

EntryGo matches
example.comthat exact host only
.example.comsubdomains only, not the bare host
*.example.comsubdomains, and Go is one of the few that accepts this form
10.0.0.0/8not supported

The portable form, which behaves the same in Go and everywhere else:

no_proxy=example.com,.example.com,localhost,127.0.0.1,::1

The other family

import "golang.org/x/net/proxy"

d, _ := proxy.SOCKS5("tcp", "198.51.100.14:1080", &proxy.Auth{User: "user", Password: "pass"}, proxy.Direct)

tr := &http.Transport{ DialContext: func(ctx context.Context, network, addr string) (net.Conn, error) { return d.Dial(network, addr) }, } ```

Note this replaces DialContext instead of setting Proxy. With this dialer the hostname is passed to the far end, so resolution happens there, which is the equivalent of the trailing h elsewhere.

Confirming it works

r, _ := c.Get("https://api.ipify.org")
b, _ := io.ReadAll(r.Body)
fmt.Println("go выходит через", strings.TrimSpace(string(b)))

Because the environment is honoured by default, run this both with and without the variables set. The two answers should differ, and they only differ cleanly when the entry is an address nobody else is using. A Go binary that works on your machine and goes direct in a container is almost always this.
