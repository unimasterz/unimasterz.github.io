Wirebound / Other runtimes

Java: system properties, ProxySelector, and the auth quirk

The only runtime here that ignores the environment entirely and takes its settings from JVM properties. Plus one default that silently breaks credentials on encrypted targets. Tested against Java 21.

sponsor

The five answers

QuestionAnswer for Java
Where the setting goessystem properties, or a ProxySelector
Environment overrideno, the environment is ignored
Who resolves the nameyour machine
Certificatesverified against the real target

System properties, not the environment

java -Dhttp.proxyHost=198.51.100.14 -Dhttp.proxyPort=8080 \
     -Dhttps.proxyHost=198.51.100.14 -Dhttps.proxyPort=8080 \
     -Dhttp.nonProxyHosts='localhost|127.0.0.1|*.internal' \
     -jar moe-prilozhenie.jar

Setting https_proxy in the shell does nothing. This catches everyone arriving from another language, and the failure is silent: the program goes direct and works.

Note nonProxyHosts uses vertical bars, not commas, and accepts * at the start. Different separator from every other tool in this reference.

In code:

System.setProperty("https.proxyHost", "198.51.100.14");
System.setProperty("https.proxyPort", "8080");

Set these before the first connection. Several parts of the JDK cache the selector on first use, so changing them later has no effect.

The modern client

HttpClient c = HttpClient.newBuilder()
    .proxy(ProxySelector.of(new InetSocketAddress("198.51.100.14", 8080)))
    .connectTimeout(Duration.ofSeconds(5))
    .followRedirects(HttpClient.Redirect.NORMAL)
    .build();

HttpRequest r = HttpRequest.newBuilder(URI.create("https://api.ipify.org")) .timeout(Duration.ofSeconds(20)) .build();

System.out.println(c.send(r, HttpResponse.BodyHandlers.ofString()).body()); ```

ProxySelector.of takes one address for everything. For per-host routing, write your own selector:

ProxySelector svoj = new ProxySelector() {
    final Proxy cherez = new Proxy(Proxy.Type.HTTP,
        new InetSocketAddress("198.51.100.14", 8080));

public List<Proxy> select(URI uri) { if (uri.getHost().endsWith(".internal")) return List.of(Proxy.NO_PROXY); return List.of(cherez); } public void connectFailed(URI uri, SocketAddress sa, IOException e) { } }; ```

connectFailed is required and is usually left empty. Logging in it is worth doing: it fires when the hop itself is unreachable, which is information you otherwise have to infer.

The authentication trap

Basic authentication for tunnels is disabled by default

A JDK security update disabled Basic scheme authentication for the CONNECT tunnel. Credentials that work for a plain http target are silently refused for an encrypted one, and the error says nothing about it.

The property that restores it:

-Djdk.http.auth.tunneling.disabledSchemes=""

An empty value re-enables Basic for tunnels. There is also jdk.http.auth.proxying.disabledSchemes for the non-tunnel case.

This was disabled for a reason: credentials in the tunnel setup travel before any encryption exists. If your provider supports a bound address, that is the better answer and needs no property at all. IPv4 access with an address allowlist removes the whole tunnel authentication question from a Java service.

Supplying credentials

Authenticator.setDefault(new Authenticator() {
    protected PasswordAuthentication getPasswordAuthentication() {
        if (getRequestorType() == RequestorType.PROXY) {
            return new PasswordAuthentication("user", "pass".toCharArray());
        }
        return null;
    }
});

The RequestorType check matters. Without it, the same credentials are offered to the target site as well, which is not what you want and occasionally causes odd failures.

Timeouts

.connectTimeout(Duration.ofSeconds(5))     // на клиенте
.timeout(Duration.ofSeconds(20))           // на запросе

The request timeout covers the whole exchange including the body, so Java gives you a real ceiling without extra work.

For the older HttpURLConnection, both setConnectTimeout and setReadTimeout must be set; neither defaults to anything finite.

Confirming it works

System.out.println("java выходит через " +
    c.send(HttpRequest.newBuilder(URI.create("https://api.ipify.org")).build(),
           HttpResponse.BodyHandlers.ofString()).body().trim());

Print the properties at startup as well. Because Java ignores the environment, the usual env | grep proxy check tells you nothing here, and that mismatch is the source of most confusion:

System.out.println(System.getProperty("https.proxyHost") + ":" +
                   System.getProperty("https.proxyPort"));
