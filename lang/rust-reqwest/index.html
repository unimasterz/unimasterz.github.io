Rust: reqwest builders and the no_proxy list

Builder based and explicit, with one counting quirk.

sponsor

The five answers

QuestionAnswer for reqwest
Where the setting goes.proxy() on the client builder
Environment overrideyes, unless disabled
Who resolves the nameyour machine, or the far end with the socks feature
Certificatesverified against the real target
The trap.proxy() adds, it does not replace

The setting

use reqwest::{Client, Proxy};

let c = Client::builder() .proxy(Proxy::all("http://198.51.100.14:8080")? .basic_auth("user", "pass")) .connect_timeout(std::time::Duration::from_secs(5)) .timeout(std::time::Duration::from_secs(30)) .pool_max_idle_per_host(20) .build()?;

let telo = c.get("https://api.ipify.org").send().await?.text().await?; println!("rust выходит через {}", telo.trim()); ```

basic_auth keeps credentials out of the url, so no percent-encoding.

Proxy::all covers both schemes. There are also Proxy::http and Proxy::https for finer control, keyed by the target's scheme in the usual way.

Calling `.proxy()` twice adds two, it does not replace the first

Each call appends to a list, and they are consulted in order. Building a client in a loop or a helper that calls .proxy() conditionally can leave you with several, and the first match wins. If you want exactly one, build the value first and call once.

Routing with a closure

let p = Proxy::custom(|url| {
    if url.host_str().map_or(false, |h| h.ends_with(".internal")) {
        None                                   // напрямую
    } else {
        "http://198.51.100.14:8080".parse().ok()
    }
});
let c = Client::builder().proxy(p).build()?;

None means direct. Same shape as Go's function and just as clear, and it replaces the need for a bypass string entirely.

The bypass list

let p = Proxy::all("http://198.51.100.14:8080")?
    .no_proxy(reqwest::NoProxy::from_string("localhost,127.0.0.1,.internal"));

Comma separated. A leading dot covers subdomains. If you pass nothing, the NO_PROXY environment variable is used.

For anything unattended I would use the closure instead: it is explicit, it lives with the code, and it does not depend on matching rules that vary by version.

Turning off the environment

let c = Client::builder().no_proxy().build()?;

.no_proxy() on the builder disables all proxy handling including the environment, which is what you want for a job that configures everything itself.

The other family

# Cargo.toml
reqwest = { version = "0.12", features = ["socks", "json", "rustls-tls"] }
let p = Proxy::all("socks5h://198.51.100.14:1080")?
    .basic_auth("user", "pass");

Without the socks feature the scheme is rejected at runtime with an unhelpful error, so if a socks url fails immediately, check the feature list first.

The socks5h spelling is honoured and moves resolution to the far end.

Timeouts

.connect_timeout(Duration::from_secs(5))     // до соединения
.timeout(Duration::from_secs(30))            // весь запрос, включая тело
.read_timeout(Duration::from_secs(20))       // между кусками

.timeout() is a genuine total, which puts reqwest in the small group here that gives you a ceiling without extra work.

Connections

.pool_max_idle_per_host(20)
.pool_idle_timeout(Duration::from_secs(90))
.http2_prior_knowledge()   // только если цель точно поддерживает

Build the client once and clone it where needed. One client per entry is the usual arrangement, so the number of clients follows how many addresses the plan includes. Client is cheap to clone and clones share the pool; constructing a new one per task throws the pool away and pays full setup every time.

Confirming it works

let a = c.get("https://api.ipify.org").send().await?.text().await?;
let pryamo = Client::builder().no_proxy().build()?
    .get("https://api.ipify.org").send().await?.text().await?;
assert_ne!(a.trim(), pryamo.trim(), "идём напрямую");

Asserting the two differ is stronger than printing one and reading it, and it turns the check into something that fails the run instead of something you have to notice.
